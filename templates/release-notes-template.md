## Template Usage

### When to Create Release Notes
- **Major releases** (v1.0.0, v2.0.0)
- **Minor releases** (v1.1.0, v1.2.0)
- **Patch releases** (v1.1.1, v1.1.2) - for significant fixes
- **Hotfix releases** (v1.1.1-hotfix.1)

### Release Notes Best Practices
- **Be specific**: Include concrete details about changes
- **Use clear language**: Avoid technical jargon when possible
- **Include impact**: Explain how changes affect users
- **Provide context**: Explain why changes were made
- **Include examples**: Show how to use new features
- **Link to documentation**: Provide links to relevant docs
- **Acknowledge contributors**: Give credit where due

### Automation
- **GitHub Actions**: Automatically generate release notes from PRs
- **Changelog**: Keep a running changelog in CHANGELOG.md
- **Templates**: Use this template for consistent formatting
- **Review**: Always review release notes before publishing

### Examples

#### Major Release (v2.0.0)
```markdown
# Release Notes - v2.0.0 - 2024-01-15

## 🎉 What's New

### ✨ New Features
- **Bitcoin Lightning Integration**: Full support for Lightning Network payments
  - Send and receive Lightning payments
  - Automatic channel management
  - Real-time payment tracking

### 🚀 Breaking Changes
- **API Version 2**: New API endpoints with improved structure
  - Old endpoints deprecated
  - Migration guide available
  - 6-month deprecation period
```
