## Template Usage

### When to Create an Incident Report
- **Critical incidents** (P1) - Always required
- **High severity incidents** (P2) - Always required
- **Medium severity incidents** (P3) - Recommended
- **Low severity incidents** (P4) - Optional

### Incident Severity Levels
- **P1 - Critical**: Complete service outage, data loss, security breach
- **P2 - High**: Significant service degradation, major feature broken
- **P3 - Medium**: Minor service issues, non-critical features affected
- **P4 - Low**: Cosmetic issues, minor bugs, non-user-facing problems

### Best Practices
- **Be factual**: Stick to facts, avoid speculation
- **Be thorough**: Include all relevant details
- **Be timely**: Complete within 24-48 hours of resolution
- **Be actionable**: Include specific action items
- **Be honest**: Acknowledge mistakes and learn from them
- **Be collaborative**: Involve all relevant team members

### Automation
- **Incident Creation**: Automatically create incident reports from monitoring alerts
- **Timeline Tracking**: Use tools to automatically track incident timeline
- **Metrics Collection**: Automatically collect performance metrics during incidents
- **Communication Templates**: Use templates for consistent communication

### Examples

#### Critical Incident (P1)
```markdown
# Incident Report - INC-2024-001 - 2024-01-15

## 📋 Incident Summary
- **Severity**: Critical
- **Duration**: 2 hours 15 minutes
- **Users Affected**: 100% of users
- **Services Affected**: All services down

## 🔍 Incident Details
### Description
Complete service outage due to database corruption. All users unable to access the platform.

### Root Cause
Database corruption caused by failed migration script that was not properly tested in staging.
```

#### High Severity Incident (P2)
```markdown
# Incident Report - INC-2024-002 - 2024-01-16

## 📋 Incident Summary
- **Severity**: High
- **Duration**: 45 minutes
- **Users Affected**: 30% of users
- **Services Affected**: Payment processing service

## 🔍 Incident Details
### Description
Payment processing service experiencing high error rates, causing payment failures for 30% of users.

### Root Cause
Memory leak in payment processing service causing gradual performance degradation.
```
