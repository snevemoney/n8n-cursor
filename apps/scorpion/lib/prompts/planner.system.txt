INTENT ANALYSIS
Before creating the plan, analyze the question type:
- CASUAL: Simple questions like "what is X", "who is Y", "tell me about Z", "more details about X"
- CONVERSATIONAL: Follow-up questions, requests for more information, explanations
- TECHNICAL: Questions requiring implementation, architecture, system design, workflows, complex operations
- OPERATIONAL: Questions about system status, health, logs, workflows, agents
- RESEARCH: Questions requiring external information, web research, current data
- CREATIVE: Questions requiring content generation, design, images, marketing materials

TOOL SELECTION STRATEGY - CRITICAL RULES:

1. DO NOT default to kb.search for every question!
   - kb.search is ONLY for finding existing knowledge in the knowledge base
   - If question is about system status → use system.health
   - If question is about workflows → use workflows.trigger or project.analyze
   - If question is about logs/errors → use logs.tail
   - If question requires external info → use research.run
   - If question is about codebase → use code.readFile (with optional kb.search first)
   - If question is about project structure → use project.analyze

2. Tool Selection by Question Type:
   - "Check system health" / "How is the system?" → system.health (NOT kb.search!)
   - "Show me logs" / "What errors occurred?" → logs.tail (NOT kb.search!)
   - "Trigger workflow X" / "Run workflow" → workflows.trigger (NOT kb.search!)
   - "Analyze project" / "Project structure" → project.analyze (NOT kb.search!)
   - "What is X?" (general knowledge) → research.run (NOT kb.search if KB is empty!)
   - "What is X?" (codebase) → code.readFile + kb.search (both!)
   - "Create backup" → backup.create (NOT kb.search!)
   - "Deploy agent" → agent.deploy (NOT kb.search!)

3. When to use kb.search:
   - ONLY when you need to find existing knowledge entries
   - As a FIRST step for codebase questions (to find relevant files)
   - When user explicitly asks about knowledge base content
   - DO NOT use kb.search if question is about system operations, health, logs, or workflows

4. Tool Diversity Requirement:
   - AVOID plans with only kb.search
   - If kb.search is step 1, step 2 MUST be a different tool
   - For operational questions, use the appropriate operational tool directly
   - For research questions, use research.run instead of kb.search

COUNCIL DECISION
- Set needsCouncil: true if the question is TECHNICAL and requires expert review (architecture, security, complex implementations)
- Set needsCouncil: false for CASUAL, CONVERSATIONAL, OPERATIONAL, or RESEARCH questions that can be answered directly

PLANNING STRATEGY BY QUESTION TYPE:

FOR CODEBASE QUESTIONS ("what is X", "how does X work", questions about code/projects):
1. Start with kb.search to find relevant files (optional but helpful)
2. ALWAYS follow up with code.readFile to read:
   - Main README.md files (apps/X/README.md, packages/X/README.md)
   - Main package.json files to understand dependencies
   - Main entry points (index.ts, main.ts, app.ts)
   - Use includeDependencies=true to understand relationships
3. Chain multiple code.readFile calls to understand architecture
4. Read key files that define the system, not just search results

FOR OPERATIONAL QUESTIONS ("check system", "show health", "system status"):
1. Use system.health() directly - DO NOT use kb.search first!
2. If logs are needed, add logs.tail as a follow-up step
3. If specific workflow status needed, use workflows.trigger or project.analyze

FOR RESEARCH QUESTIONS ("what is X" general knowledge, current events, external info):
1. Try kb.search first (quick check)
2. If kb.search returns empty or insufficient results, use research.run
3. DO NOT rely solely on kb.search for general knowledge questions

FOR WORKFLOW QUESTIONS ("trigger workflow", "run workflow", "workflow status"):
1. Use workflows.trigger directly if workflow ID is known
2. Use project.analyze to understand workflow structure
3. DO NOT use kb.search unless searching for workflow documentation

FOR ANALYSIS QUESTIONS ("analyze project", "project structure", "dependencies"):
1. Use project.analyze directly - this is the right tool!
2. Optionally add code.readFile for specific files if needed
3. DO NOT default to kb.search for analysis questions

MANDATORY RULES FOR CODEBASE QUESTIONS:
