DETAILED TOOL DESCRIPTIONS - USAGE GUIDANCE

=== KNOWLEDGE & CODE TOOLS ===

**kb.search(query, limit)**
- **What it does**: Searches the RAG/knowledge base using semantic similarity. Returns knowledge entries with relevance scores.
- **When to use it**: 
  - Finding existing knowledge entries about topics, concepts, or documentation
  - As ONE possible first step for codebase questions (but not always - vary your approach!)
  - When user explicitly asks about knowledge base content
  - DO NOT use for file tracking queries (use files.recent instead)
  - DO NOT use for "recent files", "uploaded files", "accessed files" queries
- **What it returns**: Array of hits with: id, title, url, description, content (preview), spans, relevance (similarity score 0-1), source, category, tags, metadata
- **How to use it effectively**:
  - Similarity scores help filter quality: scores >= 0.5 are typically relevant
  - Use limit parameter (1-20) to control result count
  - Results are sorted by relevance (highest first)
  - Consider skipping kb.search if you can get info more directly from code.readFile or project.analyze
  - For codebase questions, reading actual code files is often more accurate than knowledge base entries

**code.readFile(path, includeAST?, includeDependencies?, maxLines?)**
- **What it does**: Reads code files with optional AST parsing and dependency tracking. Tracks file access for conversation context.
- **When to use it**:
  - REQUIRED for codebase questions (LightningFlow, Scorpion, n8n, workflows, code)
  - Understanding implementation details, architecture, or specific features
  - Reading documentation files (README.md, package.json, etc.)
  - Vary which files you read - don't always read the same ones (README/package.json)
- **What it returns**: File content, language, path, lineCount, truncated flag. Optionally: AST (imports, exports, functions, classes), dependencies array
- **How to use it effectively**:
  - Use includeAST=true when you need to understand code structure, imports, or relationships
  - Use includeDependencies=true when you need to trace file dependencies
  - Use maxLines to limit large files (default: no limit)
  - File access is tracked automatically for conversation context
  - For "what is" questions, prioritize README.md and package.json
  - Vary file selection: config files, entry points, key modules, tests, docs

**project.analyze(scope)**
- **What it does**: Analyzes project structure, dependencies, and health. Provides overview of architecture and components.
- **When to use it**:
  - Getting project overview and structure
  - Understanding component relationships
  - Assessing project health and identifying issues
  - As an alternative starting point instead of kb.search
- **What it returns**: Summary (totalFiles, categories, lastUpdated), structure (apps, packages, tools), health (score, issues, recommendations), knowledgeBase (relevant entries)
- **How to use it effectively**:
  - Use as first step for project overview questions
  - Combine with code.readFile for specific areas
  - Use includeFiles=true to get recent file list
  - Use includeDependencies=true to understand relationships
  - DO NOT use for file tracking queries (use files.recent instead)
