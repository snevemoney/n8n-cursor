
### Shared Packages

## Environment Rules

### Local Development
- Use localhost URLs
- Mock services allowed
- Hot reload enabled
- Debug mode on

### Integration/Staging/Production
- Use 127.0.0.1 for internal services
- Expose via Caddy reverse proxy
- No localhost or 0.0.0.0 bindings
- Proper domain configuration required

## Security Requirements

### Never Do:
- Hardcode secrets or API keys
- Use 0.0.0.0 port bindings
- Mix localhost with production
- Expose internal services publicly

### Always Do:
- Use environment variables
- Bind to 127.0.0.1 internally
- Validate webhook hosts
- Check port conflicts

## UI Integrity Rules

- ✅ BusinessSidebar with 4 sections (Payments, Earnings, Boost, Settings)
- ✅ "LightningAI Flow" header

## Emergency Procedures

### If UI Breaks:
1. Check ROLLBACK.md
2. Run self-check: `curl http://localhost:3002/__selfcheck`
3. Verify port conflicts: `lsof -i :3002`
4. Restart on clean port: `PORT=3003 npm run dev`

### If Scope Bleed:
1. Check PROJECTS.yaml
2. Verify changed files against allow_globs
3. Revert out-of-scope changes
4. Update PR title format

### If Environment Issues:
1. Run env validator: `tsx scripts/validate/env-validator.ts [project] [env]`
2. Check forbidden patterns
3. Verify allowed hosts
4. Update environment files

## Reliability Contract (MUST FOLLOW)
- **Goal**: lightningflow.online and evenslouis.ca/n8n NEVER break
- **Any change** that touches infra, routes, ports, env, or Docker MUST:
  1) Preserve /healthz endpoints for web, api, n8n
  2) Keep all container ports bound to 127.0.0.1; public ingress ONLY via Caddy
  3) Include Compose healthchecks and resource caps
  4) Provide a rollback step (previous image tag or blue/green switch)
  5) Update/confirm Caddy routes for both domains
- **If change risks downtime**, propose blue-green plan first. If not provided, REFUSE and ask for a safe plan
