# Nondilutive funding scan

**Owner:** Money Desk + Researcher. **HITL:** Tier 3 before any application or paid tool.
**Source:** yt:L8pR2YAV8Fw Google Cloud Tech / The Agent Factory — watch-page **PROVE** (timedtext CAPTION_GAP). Guest Thierry Lindor / Happly.ai. Remap guest product → Grok + Cursor research + propose.

## When
Operator (Canada / startup) wants a cheap read of grants, loans, procurement, wage subsidies, or tax credits that do **not** sell equity. Not a buy-automation SKU. Adjacent to nate-five-buy-workflows.

## Do
1. **Match programs only.** Profile (jurisdiction, stage, sector, identity-adjacent eligibility as stated on official pages) → short candidate list. Prefer official Canada / provincial / federal pages over a SaaS pitch.
2. **Draft only.** One-page checklist: program · deadline · fit · docs needed · next human step. No autofill-to-submit.
3. **Cheap read.** Scanning is match-model-to-task. Submitting, paying Happly, or treating traction $ as FACT is expensive.
4. **Propose-first.** Happly.ai signup, Chrome extension, grant-writer marketplace, or any paid scan = **Tier 3**. Do not install. Do not store API keys in notes.
5. Label guest/creator $ and pool sizes **UNVERIFIED** until a desk proves them (84k users · $90M landed · $2T NA pool · Black Entrepreneurship Program $265M = FACT-as-stated, not re-audited).

## Don't
- Auto-submit grants or click-apply via an extension
- Install Happly / Gemini-inside-Happly / any autofill agent
- Dilute early "because sharks" without a scan (guest OPINION — keep as caution, not a rule to raise)
- Quote traction $ as hive FACT
- Mint a new business lane from this tape

## Done when
Dated draft checklist on disk (packet or Money-desk note) + operator yes/no on next step. Not a submitted form.

# Grant proposals: nonprofit, RFP, elements, funder, revise (clustered)

**Use when:** a prompt needs a **coherent, persuasive grant proposal** for a project or initiative — nonprofit/NGO basics and how they acquire funding, **RFP/RFA** reading and assessment, **key elements** (abstract through evaluation plan), **sources and funder relationships**, then **write and revise** — in the Saylor PRDV009 **Writing Grant Proposals** school (13 h adult-learner PD).

**Do not use when:** reconstructing exams; **PRDV002** workplace emails/reports; **PRDV010** evaluating sources/references as a *course*; **ENGL*** composition (Publishing — do not write those packets); promising ACE; **sending** or filing a live proposal to a funder; treating US federal forms as the only live checklist.

This is **one** skill. Five live units are one loop: **know the nonprofit funding job → read the call → assemble elements → find and keep funders → write/revise.**

## 0. Hygiene

- Label **school**. Saylor **PRDV009**. LMS **862**. Catalog **13 h / 1.3 CEU**. ACE **N**. Certificate: **70%**; **14-day**; **max 3**. Not a degree twin. Not ENGL.
- Label **claim vs data**. Guest only. Units never opened. No guest textbook. No intro-video activity. AI zone `102934`. Stale **id=442 / 12 h / 2020.A.01** — **do not encode**. Live intro: US-specific references; principles relevant to most countries. **No LMS Chrome** until BUS403. **No cert final.**
- Grant writing ≠ workplace writing ≠ source-evaluation ≠ composition. **PRDV002** *writes workplace genres*. This skill *answers a funding call*.
- Live intro: nonprofit organizations and NGOs; interpret RFPs; elements from **abstract to evaluation plan**; find sources; build funder relationships; practical write/revise tips.
- No exam items. Summarize OER. Do not dump sample proposals. **Do not send** the proposal — HITL / money-adjacent if it would go to a funder.
- Five **live** CLOs map 1:1 to the five units (suggested).

## 1. Procedure — five checks

Run in order.

### Check A — Identity overlay (always)

| Prompt smells like | Hand off |
|---|---|
| "Email / report / blog as workplace writing" | **PRDV002** |
| "Cite this source / evaluate this reference" | **PRDV010** |
| "Essay / composition" | **ENGL*** (Publishing) |
| "Personal budget / global financial literacy" | **PRDV011** |
| "Read this RFP, structure the proposal, approach this funder" | **this skill** |

**Primary goal:** a coherent, persuasive funding request that matches the call. Named failure mode: writing the narrative before reading the RFP, or submitting without HITL.

### Check B — Nonprofit / NGO and why grants (when "who even needs this money" is in play)

CLO 1. Unit 1.

**Characterize nonprofit organizations and how they acquire grant funding.** Live intro: why they need funding; steps in acquiring it. NGOs named alongside nonprofits.

### Check C — RFP / RFA and how it is assessed (when "what is this call asking" is in play)

CLO 2. Unit 2.

**Summarize calls for grant funding and how grant applications are typically assessed.** RFP **and** RFA are live unit-title language. Encode the *job* (what the call actually requires). Do not invent a live federal-form number as CLO language.

### Check D — Elements of the proposal (when "what goes in the packet" is in play)

CLO 3. Unit 3.

**Describe the key elements of a grant proposal and how to create your funding request.** Live intro: step-by-step from **abstract to evaluation plan**. Follow the RFP; if no RFP, typical well-thought-out elements (SNLS residue — confirm live list on login; do not freeze a named 12-part federal outline as live).

### Check E — Funders, then write/revise (when "who pays / how do I draft" is in play)

CLO 4–5. Units 4–5.

**Identify potential sources** and **explain how to develop relationships with funders.** **Apply useful tips for writing and revising.** Unit 5 live residue: connect the pieces before sitting down to write; review after the first draft.

Do **not** mail the proposal. Draft here.

## 2. Worked patterns (shape only)

**"Community org wants a first grant for after-school."**
Check A (grant, not a blog) then B (nonprofit funding job) then C (find/read an RFP) then D (elements matching the call) then E (sources + draft). Not PRDV002's email. Not sending.

**"We have a 20-page narrative and ignored the RFA page limits."**
Check C first (how applications are assessed) then D (elements the call actually wants) then E (revise). Failure mode: Unit 5 before Unit 2.
