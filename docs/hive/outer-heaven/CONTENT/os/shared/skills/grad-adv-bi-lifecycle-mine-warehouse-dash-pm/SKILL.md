# Graduate advanced BI: lifecycle, mine, warehouse, dashboard, produce (clustered)

**Use when:** a task asks how a firm's **BI function** should support managerial decisions at a named stage of the enterprise lifecycle — which sources to collect and filter, how to mine data *and* text, which warehousing/integration approach fits *this* case, how to exploit data into an actionable analysis, which KPI visualization or dashboard the decision-maker needs, or how to run intelligence production as a project — in the Saylor BUS610 **graduate** advanced-BI school.

**Do not use when:** the job is reconstructing or taking a Saylor (or any) exam, dumping Davenport/Kimball/Tableau/PMBOK/CAP item banks, running **BUS250** undergraduate introduction to BI (warehouse + named tools + legal as intro), **BUS204** stats-as-inference, **BUS206** MIS five-components, **CS250** pandas/scikit-learn implementation, **BUS607** graduate D3M / bias / CRM / leadership as a *course*, **BUS611** DBMS/data-management plan, **BUS612** / **PRDV200** data communications as a course, **BUS605** / **BUS402** project management as a *course*, treating the free 70% certificate as **MBA610** / **MMKT607** 80% proctored exams, promising ACE/transfer credit, or inventing a live tool stack / Inmon-Kimball doctrine.

This is **one** skill. It is not "Unit 1 skill + Unit 2 skill…". BUS610's eight live units are one argument: **stand up the BI function across the firm lifecycle so collect → filter → mine → warehouse/integrate → analyze → report/dashboard actually produces decision-maker-focused intelligence, run as a project, because a bad managerial choice can kill the firm.**

## 1. Procedure — answer a graduate advanced-BI question in six checks

Run in order. Skip a check only if the user already constrained the frame.

### Check A — Identity, lifecycle, overlay (always)

**The course question:** is the user asking for an **intro BI definition**, a **stats inference** answer, an **MIS survey**, a **Python implementation**, a **manager's D3M decision**, a **DBMS plan**, a **comms course**, a **PM course**, or a **BI function** that has to feed decisions across the firm's life?

Live test:

| Prompt smells like | Hand off |
|---|---|
| "What is BI / warehouse / Tableau as intro" | **BUS250** |
| "Sample, CLT, p-value, regression as inference" | **BUS204** |
| "Five components, CIA, does IT matter" | **BUS206** |
| "pandas / fit a sklearn model / spaCy" | **CS250** |
| "Which decision, which bias, CRM file, uses vs misuses" | **BUS607** |
| "Pick a DBMS / write the data-management plan / SQL" | **BUS611** |
| "Slide narrative / accessibility / data comms as a course" | **BUS612** / **PRDV200** |
| "PMI ten knowledge areas / charter to close as a *course*" | **BUS605** / **BUS402** |
| "Stand up the BI team / mine text / warehouse *this* case / dashboard the decision-maker / produce intelligence as a project" | **this skill** |

**Primary goal:** intelligence the management team can **use** at this lifecycle stage, from reliable sources, in a format they can understand. That is not "pass Tableau," not "beat a hunch" as a *course* (**BUS607**), and not "define BI" as intro (**BUS250**).

**Named live failure mode:** a wrong managerial choice that hits the bottom line and can kill the firm (shampoo parable scaled up).

**Lifecycle stages named in the live intro** (encode these, confirm live labels): **start-up → growth → competition battles → maturity and reinvestment or reinvention to prevent decline.** How and when to focus on specific BI applications **changes with the stage**. A start-up mining product-review text is not the same job as a mature firm integrating five legacy warehouses.

**Level check:** if the prompt is actually undergrad homework in BUS250's eight units, **hand off BUS250** and recap only. If it is MBA610/MMKT607's proctored 80% exam, **refuse exam reconstruction**; this skill is the *content* overlay, not the degree exam.

### Check B — Support the decision at a level, in an org type (when "who decides / operational or strategic / startup vs mature" is in play)

CLO 2–3. Units 1–2.

BI is **support**, not the decision. Name:

1. **Who** is deciding (and at which level — operational / tactical / strategic if they said; confirm live labels).
2. **What kind of organization** (lifecycle stage from Check A; product vs service; maybe international as a *reading overlay*, not as BUS613).
3. **What kind of decision** — indexed residue (label archive): avoiding / problem solving / problem seeking. Confirm live names. Encode the *job* even if the triad is unconfirmed: is the manager avoiding a choice, solving a known problem, or seeking a problem they have not named yet?

Indexed Unit 1 overlay (archive): BI ≠ information management (TPS reporting) ≠ data processing (OLTP / SQL). Four roles — CDO, data scientist, CAO, data manager — plus a data-literate culture. Use as *candidate* org design for the BI function; **do not require the four titles as live CLO language**.

**Hand off BUS607 Unit 3** if they want leadership-as-champion-of-evidence as a *course*. **Hand off BUS208 / BUS401 / BUS603** for POLC / theory families / managing people. Stay here for "this BI product has to support *this* decision at *this* level."

### Check C — Mine data and text (when "pattern / unstructured / reviews / tickets / basket / churn" is in play)

CLO 4. Unit 3.

**Both** processes are first-class. Data mining without text mining fails the live CLO. Text mining without a managerial question is an NLP demo (**CS250**).

Process depth (Gallaugher named pattern-classes, do not dump): segment, target, basket, collaborative filter, churn, fraud, hire. Encode "extract a pattern a manager can act on," not a library import.

Text: reviews, social, tickets, contracts — unstructured feeds become intelligence. BUS250 already admitted social-media text as a *source* and sentiment/word-cloud as *viz*. Here you **mine** it.

**Rules:**

- Do not invent a named NLP stack (spaCy / transformers / LDA) as Saylor doctrine until login.
- Do not run BUS204's hypothesis test on the cluster. If the prompt is "is this sample different," **hand off BUS204**.
- **Hand off BUS607 Unit 7** if the job is "the customer *file* as CRM strategy." Stay here for "the BI function's mining process."

### Check D — Warehouse and integrate for *this* case (when "where does it live / lake vs warehouse / we have five systems" is in play)

CLO 5. Unit 4.

The CLO is **evaluate approaches for your business case**, not "define a warehouse" (**BUS250** Unit 3) and not "pick MySQL vs Oracle / write the plan" (**BUS611**).

Live intro: **collect and filter** before you analyze. Gallaugher overlay (summarize): TPS is not a warehouse; mart vs enterprise warehouse; data-rich / information-poor; relevance, sourcing, quantity, quality, hosting, governance.

**Integration** is in the unit title. Can these sources actually sit together for *this* lifecycle stage and *this* decision (Check B)?

Do **not** guess Inmon vs Kimball vs data-lake as live Saylor doctrine. Name the *job* (what must be integrated, for whom, at what freshness) and leave the branded approach until login names it.

**Hand off BUS611** for engines, SQL, the data-management *plan* (that course even has its own warehousing unit — different seat). Stay here for "this BI case needs *this* approach."

### Check E — Analyze, then ship KPI products and dashboards (when "what did we learn / show the KPI / build the dashboard" is in play)

CLO 6–8, 10. Units 5–7.

**Analyze (Unit 5).** Select appropriate data sets, extract and exploit, produce an analysis, infer **actionable** information. Actionable = a manager can change an operation or a choice. A finding that cannot change a Unit 2 decision fails Unit 1's survival criterion.

Analytics levels (public school; **confirm live names** — not a live CLO list):

| Level | Asks | Fail if you stop here |
|---|---|---|
| Descriptive | What happened? | A report nobody decides from |
| Diagnostic | Why did it happen? | A story with no next action |
| Predictive | What will happen? | A forecast nobody owns |
| Prescriptive | What should we do? | A recommendation with no constraint |

Do not force BUS250's extra **cluster** as a fifth live level unless login says so. **Hand off BUS204** for inference machinery. **Hand off CS250** for the fit.

**Report / viz (Unit 6).** Common **KPI** → visualization **products** that improve **internal business processes**. KPI is named in this course's CLO (it was **not** named on BUS250's public intro). Product ≠ poster.

**Dashboards (Unit 7).** First-class unit. CLO 10: products are **decision-maker focused** and **aligned with BI requirements**. A dashboard that cannot answer the Unit 2 decision at the Unit 2 level is wallpaper. OLAP slice-and-dice explores; the dashboard *heads-up* critical indicators (Gallaugher overlay, summarize).

| Audience | Needs | Fail |
|---|---|---|
| Board / ELT | Decision, stake, risk, one view | A 40-tile dump |
| Function lead | Exception + trend vs a named KPI | Vanity metrics |
| Analyst | Grain, filters, drill | A PNG they cannot interrogate |
| Front line | What to do *this shift* | A warehouse schema |

**Hand off BUS612 / PRDV200** if they want comms-as-a-course. **Hand off BUS250 Unit 5** for intro chart types. **Hand off BUS607 Unit 6** for viz-as-the-leader's-D3M-story. Stay here for "the BI function's product."

### Check F — Produce it as a project (when "the warehouse never ships / requirements keep moving / who is the customer of this dashboard" is in play)

CLO 9–10. Unit 8.

The **intelligence production process** is how BI improves organizational decision-making. That process is a **project**: scoped to a decision-maker, with requirements (CLO 10), not an endless platform build.

Live pipeline: collect → filter → analyze → report. Unit 8 is how you *run* it so a product actually lands in time for the Unit 2 decision at the Check A lifecycle stage.

**Hand off BUS605 / BUS402** if they want PM as a *course* (ten knowledge areas, ACE intro, etc.). Stay here for "this intelligence product, these BI requirements, this decision-maker."

Indexed culture overlay: a data-literate firm asks better questions. Production that the org cannot read is a Unit 8 fail, not a Unit 6 pretty-chart fail.

## 2. Worked micro-patterns

**"What is advanced BI / how is it not intro BI or D3M?"**
Check A in one paragraph. BI *team* + collect/filter/analyze/report. Goal = intelligence managers can use at this lifecycle stage. Fail = a choice that can kill the firm. Hook: BUS250 *teaches* warehouse/dashboard/models; BUS607 *decides*; this course *runs the function* that feeds the decision. Name the overlays: BUS204 infers; BUS611 stores; BUS612 tells the story as a *course*; BUS605 is PM as a course.

**"We're a start-up / we're fighting a price war / we're mature and declining."**
Checks A then B then E. Stage changes which BI application you focus on (live intro). Do not ship a mature-firm enterprise warehouse to a five-person start-up. Do not ship a growth dashboard with no competitive feed during a rivalry stage.

**"Mine the reviews / tickets / social / basket."**
Check C. Data *and* text. Pattern → action. No Python. No CRM-as-a-course (**BUS607** Unit 7) unless they actually want the file as campaign object.

**"Lake vs warehouse vs mart / five legacy systems / ETL."**
Check D. Evaluate *for this case*. Integration is the named extra. Do not guess Inmon/Kimball. Do not write BUS611's plan.

**"Show the KPI / build the dashboard / the board cannot read this."**
Check E then F. KPI is a live CLO. Dashboard is its own unit. Decision-maker focused + aligned with BI requirements. If it never ships, that is Unit 8, not Unit 7.

**"p-value / confidence interval / fit this OLS."**
Wrong course. **BUS204**.

**"pandas / scikit-learn / fine-tune a sentiment model."**
Wrong course. **CS250**. Recap that text mining is in-scope here as a *process*, not as a notebook.

**"Anonymize vs pseudonymize / GDPR playbook."**
Wrong first-class unit. **BUS250** Unit 8 owns that intro CLO. BUS607 Unit 8 owns uses/misuses as a *course*. Here privacy is a *constraint on the product* (Gallaugher overlay) — name it, then stay on production.

**"MMKT609 advanced BI."**
That code is **Data-Driven Decision-Making** (BUS607-class). The marketing BI twin is **MMKT607**. MBA twin is **MBA610** (program listing may drop Advanced). MEI610 is a seminar.

**"Charter, WBS, ten knowledge areas."**
Wrong course unless they only need "this intelligence product is a project." **BUS605** / **BUS402**.
