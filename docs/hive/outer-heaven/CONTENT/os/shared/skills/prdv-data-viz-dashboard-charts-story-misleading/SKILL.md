# Data viz: dashboard theory, charts, scan misleading, tell the story (clustered)

**Use when:** a prompt needs **data visualization as communication** — dashboard-design foundations, industry benefits, basic charts, scan for misleading, pick a method, tell a story — in the Saylor PRDV200 **Communicating with Data** school (9 h). **Never invent numbers. Never send.**

**Do not use when:** reconstructing exams; **PRDV007** presenting data *in spreadsheets*; **PRDV004** beginner Excel; **PRDV420** R (viz unit lives there as code); **PRDV008** stand-up presentations; quoting **operator FACT** balances (Personal CFO); promising ACE; **sending** the deck; treating a 2022 McKinsey line as 2026 verified research.

This is **one** skill. Four live units, six CLOs. Loop: **foundations/benefits → understand the data → charts + method + scan misleading → presentable story.**

## 1. Procedure — six checks

Run in order. Stop if Check A says another school or invented numbers.

### Check A — Identity overlay (always)

| Prompt smells like | Hand off |
|---|---|
| "How do I make this chart *in Excel*" | **PRDV007** (or PRDV004 if beginner sheets) |
| "ggplot / RStudio" | **PRDV420** |
| "Stand up and walk the room through slides" | **PRDV008** |
| "What is *my* real number / runway" | **Personal CFO** |
| "Turn this data into an honest visual story / dashboard" | **this skill** |
| "Send the deck / publish the dashboard" | **HITL — refuse send** |

**Primary goal:** a presentable visualization that tells a true story for *this* application. Named failure mode: pretty chart, wrong method, misleading dashboard, or invented numbers.

### Check B — Foundations and benefits (when "why viz / what is a dashboard" is in play)

CLO 1–2. Unit 1.

**Identify the foundations of dashboard design theory.** **Summarize the benefits of data visualization practices in industry.** Live: how people process visual information; dashboard-design principles; competitive edge.

Shape: name the audience and the decision the viz is for, then the theory/benefit. Do not cite McKinsey 2022 as current FACT. Do not skip to chart junk.

### Check C — Understand the data (when "what even is this dataset" is in play)

Unit 2 overlay (no dedicated CLO named "understand data"). Live intro: quantitative and qualitative; data-science terminology; manage data.

Shape: name the grain, the measures, quant vs qual, what is missing. If the numbers are operator FACT and you don't have them, stop — Personal CFO. Do not fill gaps with invented values.

### Check D — Charts and method (when "which chart / make one" is in play)

CLO 3, CLO 5. Unit 3.

**Create basic charts.** **Select an appropriate visualization method for a particular application.** Live: analytics with a set of charts.

Shape: application first, then the method, then a *basic* chart. Hand PRDV007 if the job is Excel mechanics. Hand PRDV420 if the job is R. Stay here for *which* visual and *why*.

### Check E — Scan misleading (when "does this chart lie" is in play)

CLO 4. Units 1/3 overlay (dashboard scan).

**Scan dashboards for misleading content.** Always-on when a viz already exists.

Shape: truncated axes, cherry-picked windows, 3D junk, missing comparators, qual dressed as quant. If the underlying number is UNVERIFIED, say so. Do not "fix" it by inventing a better number.

### Check F — Tell the story (when "present this / dashboard for the meeting" is in play)

CLO 6. Unit 4.

**Build a presentable data visualization that tells a story.** Live: organize information into visualizations to tell a story; present results.

Shape: one story, one audience, one presentable artifact. Hand **PRDV008** if they then need to *deliver* it as a talk. **Refuse send.** Do not publish.

## 2. Worked patterns (shape only)

**"Bar or line for monthly revenue?"**
Check A then C (is the grain monthly?) then D (method for *this* application). Do not invent the revenue.

**"This dashboard makes the dip look tiny."**
Check E first. Then D if they need a less misleading method. Then F if it still has to go to a meeting. Still no send.

**"McKinsey said problems are solved in hours now, put that on the slide."**
Check B + hygiene: syllabus is a *2022 prediction for 2025*; guest intro is present tense. Do not encode as 2026 verified. Label claim vs data on the slide or cut it.

**"Build the Excel and the story."**
Recap D–F here, hand sheet mechanics to PRDV007. Still no invented metrics.

**"Walk this into the room as a talk."**
Check F then PRDV008. Still HITL if it would go to a client.
