# Graduate data-driven communications: objective, picture, evaluate, story (clustered)

**Use when:** a task asks how a practitioner should **select and structure analysis results for visual communication** — which business objective the picture must serve, which data to source, which analysis is enough to have a finding, which visualization principles/processes/tools (including interactive visualizations and dashboards) to use, whether the picture is honest, or how the finding should be told as a data story — in the Saylor BUS612 **graduate** data-driven-communications school.

**Do not use when:** the job is reconstructing or taking a Saylor (or any) exam, dumping Knaflic/Tufte/Tableau item banks, running **BUS611** graduate data management (DBMS, plan, SQL, open-data, warehouse-as-asset), **BUS610** graduate advanced BI (lifecycle, text mining, warehouse-*approaches-for-a-case*, dashboards-as-intelligence-products, intelligence production), **BUS250** undergraduate introduction to BI (warehouse + named tools + legal as intro), **BUS210** undergraduate business communication (audience/purpose/channel/memo/crisis as a *course*), **BUS607** graduate D3M / bias / CRM / leadership as a *course* (viz there is how leaders *decide*), **PRDV200** 9 h mini communicating-with-data, **CS250** matplotlib implementation, treating the free 70% certificate as **MBA612 / MMKT608** 80% proctored exams, promising ACE/transfer credit, or inventing a live Tableau/Tufte stack.

This is **one** skill. It is not "Unit 1 skill + Unit 2 skill…". BUS612's six live units are one argument: **name the objective, source, and analyze only so there is a finding; then select and structure that finding for visual communication — principles, tools including interactive viz/dashboards, evaluate the picture, tell the story — because a data explosion without a communicated asset is just more bits.**

## 1. Procedure — answer a graduate data-driven-communications question in six checks

Run in order. Skip a check only if the user already constrained the frame.

### Check A — Identity, objective, overlay (always)

**The course question:** is the user asking for an **intro BI definition**, a **stats inference** answer, an **MIS survey**, a **Python implementation**, a **DBMS/plan**, a **manager's D3M decision**, a **BI function across the lifecycle**, a **general bizcomm memo**, a **9 h mini viz**, or a **visual communication job** that has to name an objective, source, analyze, picture, evaluate, and story?

Live test:

| Prompt smells like | Hand off |
|---|---|
| "What is BI / warehouse / Tableau as intro" | **BUS250** |
| "Stand up the BI team / mine text / warehouse *this* BI case / dashboard as an *intelligence product*" | **BUS610** |
| "Sample, CLT, p-value, regression as inference" | **BUS204** |
| "Five components, CIA, does IT matter" | **BUS206** |
| "pandas / matplotlib / fit a sklearn model" | **CS250** |
| "Pick a DBMS / write the data-management plan / SQL create-edit-retrieve / share or not" | **BUS611** |
| "Which decision, which bias, CRM file, uses vs misuses" | **BUS607** |
| "Memo, standup, crisis letter, intercultural assignment, meeting" | **BUS210** |
| "Create a basic chart / scan a dashboard / 9 h viz mini" | **PRDV200** |
| "Which objective, which source, which viz, is this chart honest, tell the data story" | **this skill** |

**Primary goal:** select and structure data for **visual communication** so findings, helpful facts, and data insights **convey** and everyday business data becomes a **competitive-advantage asset**. That is not "pass Tableau," not "write the DBMS plan" (**BUS611**), not "stand up the BI team" (**BUS610**), and not "define BI" as intro (**BUS250**).

**Named live failure mode:** the firm generates data (even analyzes it) and still cannot **communicate** it visually. Collection or analysis without a visual-communication job is not this course's pass. Unit 1 names the other failure: a beautiful picture of the **wrong objective**.

**Level check:** if the prompt is actually undergrad homework in BUS250's eight units, **hand off BUS250** and recap only. If it is BUS210 homework, **hand off BUS210**. If it is MBA612's / MMKT608's proctored 80% exam, **refuse exam reconstruction**; this skill is the *content* overlay, not the degree exam.

### Check B — Objective then source (when "what are we even charting / where did this data come from / wrong question" is in play)

CLO 1–3 gathering half. Unit 1.

Name, in order:

1. **The business objective** (what claim or decision this communication has to serve). OpenStax §8.1 overlay (summarize): problem definition is step 1 — acquisition is not a fishing trip.
2. **The gathering methodology** (identify/define, then differentiate, then apply — the live CLO ladder). Internal operations vs external feeds is the public-school split (confirm live labels). Full source taxonomy at *intro* → **BUS250** Unit 2. Full store/plan → **BUS611**.
3. **Whether this source can actually speak to this objective.** A beautiful chart of the wrong source still fails Unit 1.

Gallaugher overlay (summarize): data vs information vs knowledge; TPS / loyalty / CRM / aggregators as *feeds*, not as the story.

Do **not** start in Tableau. Objective before tool.

### Check C — Analysis so there is a finding (when "what did we actually learn / which method or model" is in play)

CLO 1–3 analysis half. Unit 2.

The viz is of a **finding**, not of a hunch. Identify/define, differentiate, and apply **analysis processes, methods, and models**. The analysis has to be *sayable*, not merely computed. Encode the *job* (what was compared, summarized, modeled) and leave branded method names until login.

OpenStax §8.1 overlay (summarize, **do not dump iris/Python**): patterns; correlation is not causation; interpretation is usually a visualization.

**Hand off BUS204** if they want inference as a *course*. **Hand off BUS610 Units 3/5** if they want mining / producing an analysis as the BI *function*. **Hand off BUS607** if they want "beat the bias / decide." Stay here for "the analysis this communication is of."

### Check D — Principles, then tools (when "how should this look / which chart type / which tool / dashboard" is in play)

CLO 4–7, Unit 3; CLO 8, Unit 4.

**Principles and processes first (Unit 3).** Graphic-design principles, storytelling *styles*, and **theoretical aspects of visualization design** — identify/define then differentiate. Two theories that recommend opposite encodings cannot both be "whatever looks nice." Public school (confirm live labels; do not freeze Tufte/Gestalt as Saylor doctrine): signal vs noise; chart-type fit; clutter; accessibility; process (audience, comparison, residual message). BUS210 owns C.R.A.P. / slide craft — recap, do not paste.

**Then tools and techniques (Unit 4).** CLO 8: **describe interactive visualizations and dashboards.** Describe, not "pass Tableau Desktop." Search-indexed `68990` residue (label archive): choose the **appropriate graphic presentation**; the **correct graph or chart** improves presentations *and* the data-driven decision-making process. Encode chart-type *fit*. OpenStax names Excel / Tableau / Power BI as *industry examples* — **not** a live Saylor CLO list.

Gallaugher overlay (summarize): canned vs ad hoc query; dashboard / OLAP as the managerial container. BUS610 Unit 7 owns dashboards as *intelligence products*. Here the dashboard is a **technique** that still has to be evaluated (Unit 5) and storied (Unit 6).

**Hand off PRDV200** to create a *basic* chart in the mini. **Hand off CS250** to implement. **Hand off BUS610 Units 6–7** to ship a KPI viz *product* as the BI function. Stay here for the graduate comms overlay.

### Check E — Evaluate the viz (when "is this chart honest / accessible / fit for the objective" is in play)

Unit 5. Distinctive first-class unit.

Run the test against Unit 1's objective and Unit 2's finding:

- Does this viz serve **this** objective?
- Does it tell the truth of **this** analysis (truncated axis, cherry-picked source, 3-D junk, extra-ink, inaccessible encoding)?
- Can the intended audience read it? Is the interactive dashboard *explorable* or just noisy?
- Indexed 68990: the *correct* graph is the one that improves the presentation *and* the decision process — evaluation is not aesthetics-only.

PRDV200's "scan dashboards for misleading content" is the mini version — recap, do not replace. BUS607 Unit 8 is uses/misuses of *analytics for decisions* as a *course*. BUS250 Unit 8 is legal/ethics including anonymize. Stay here for **this chart, this evaluation**.

### Check F — Story the findings (when "tell the story / present the finding / residual message" is in play)

CLO 4–5 spent, CLO 9. Unit 6.

Sequence: objective → source → analysis → designed viz → evaluated viz → **story**. CLO 9: **identify and describe visual presentations of data analysis findings**. Catalog payload: **findings, helpful facts, and data insights**. A gallery of charts with no residual message fails. A story without a Unit 1 objective is a slide deck. A story without Unit 5 evaluation is decoration.

Knaflic *Storytelling with Data* is the **ARR title-match** — name the job (context, audience, clutter, residual message), **do not dump the book**. Public-school triad (data + visual + narrative) is a vendor commonplace — **not confirmed as Saylor's list**. Encode the *job*: the finding has to travel.

Dashboard here is a *form of the story*, not BUS610's dashboards-as-BI-function unit and not BUS607's "visualizations so leaders can decide" as a D3M course. BUS210 Unit 5 is oral/nonverbal presentation technique — recap audience only, do not paste BCS.

**Hand off BUS611** if they still do not have a trustworthy store. **Hand off BUS610** if they need the BI team to *produce* the intelligence. **Hand off BUS607** if the prompt is the *decision*. Stay here for "this data story, this visual presentation of findings."

## 2. Worked patterns (shape only — not exam items)

**"Leadership wants a dashboard of everything in the warehouse."**

**"This bar chart went to the board and they decided the wrong thing."**
Check E (evaluation: misleading encoding? wrong source?) → Check B (objective/source mismatch) → Check C (was there a finding, or a hunch in chart clothing?) → Check F (story/residual message).
