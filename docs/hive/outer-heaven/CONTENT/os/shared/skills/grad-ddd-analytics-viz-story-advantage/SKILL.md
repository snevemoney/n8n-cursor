# Graduate DDD: analytics → viz story → advantage (clustered)

**Use when:** a task asks how a firm should decide from data rather than intuition — how to transform into a data-driven enterprise, which continuum is lagging, what leadership must do, which data type or analytics level the decision needs, how to turn customer-trend analysis into a visualization story an audience can use, how CRM/database marketing spends that insight, or how to catch a misuse — in the Saylor BUS607 **graduate** data-driven-decision-making school.

**Do not use when:** the job is reconstructing or taking a Saylor (or any) exam, dumping OpenStax / Bourgeois / HBR / Tufte, running **BUS204** undergraduate business statistics (hypothesis tests, CLT, simple regression as *inference*), **BUS250** intro BI (warehouse / dashboards / tools as a *course*), **BUS206** MIS survey, **BUS610** advanced BI lifecycle, **BUS611** data-management plan, **BUS612** / **PRDV200** data-comms as a *course*, **CS250** Python notebooks, treating the free 70% certificate as **MBA607** / **MMGT607** / **MMKT609** 80% proctored exams, promising ACE/transfer credit, or writing a surveillance stack.

This is **one** skill. It is not "Unit 1 skill + Unit 2 skill…". BUS607’s eight live units are one argument: **replace intuition with analytics so the firm’s decisions create competitive advantage, then refuse the misuses that fake that claim.**

## 1. Procedure — answer a graduate DDD question in six checks

Run in order. Skip a check only if the user already constrained the frame.

### Check A — Identity, goal, overlay (always)

**The course question:** is the user asking for an **inference lab**, an **intro-BI stack**, a **Python notebook**, a **comms deck as a course**, or a **manager’s decision** that is supposed to create competitive advantage with evidence?

Live test:

| Prompt smells like | Hand off |
|---|---|
| “t-test / CLT / p-value / simple regression as inference” | **BUS204** |
| “warehouse, mining, dashboards, named BI tools as intro” | **BUS250** |
| “five IS components / ERP / CIA” | **BUS206** |
| “BI lifecycle / 83-hour advanced analytics project” | **BUS610** |
| “pick a DBMS / data-management plan” | **BUS611** |
| “data-driven *communications* as the course” | **BUS612** / **PRDV200** |
| “pandas / sklearn / iris notebook” | **CS250** |
| “STP / brand / marketing mix as the course” | **BUS203** / **BUS602** |
| “trait/transformational leader” | **BUS401** |
| “motivate the standing workforce as a *course*” | **BUS603** |
| “which evidence, which continuum, which viz story, toward what advantage” | **this skill** |

**Primary goal: create competitive advantage** by deciding from data rather than intuition. That is not “ship a dashboard,” not “maximize this quarter’s NI,” and not “pass a BI cert.” Live intro: strategic **and** operational decisions; bias/false assumptions are the failure mode.

**Named live case (Google People Analytics):** reviews + surveys → manager behaviors that raise happiness → longevity → productivity. Encode as “HR is allowed to be a data object.” Full HR/OB course → **BUS301 / BUS603**.

**Level check:** if the prompt is actually undergrad homework in BUS204 or BUS250, **hand off** and recap only. If it is MBA607/MMGT607/MMKT609’s proctored 80% exam, **refuse exam reconstruction**; this skill is the *content* overlay, not the degree exam.

### Check B — Transform and lead (when “become data-driven / culture / why isn’t this sticking” is in play)

CLO 2–3.

**Three continuums (CLO 2; Bennett/HIMSS names match the live CLO — confirm on login):**

| Continuum | Job | Failure if it runs ahead |
|---|---|---|
| Data / technology | Capture, integrate, analyze | A lake nobody uses |
| People / organization | Skills, incentives, who may decide | Analysts as a report factory |
| Process / workflow | Where the decision actually sits | Insights that never touch ops |

Advance them **together**. Tech-only “we bought Tableau” is not transformation.

**Leadership (CLO 3):** set the question, fund the evidence, protect it from politics, **act**. A dashboard with no owner is not leadership. **Hand off BUS401** for theory families. Stay here for “the leader makes data the way this firm decides.”

OpenStax Analytics 1.0 / 2.0 / 3.0 is a named era overlay (HBR not CC). Name the eras; do not dump Davenport.

### Check C — What data, which analytics level (when “what do we have / how deep should we go” is in play)

CLO 4.

**Data types (school-common; confirm live labels):** structured vs unstructured vs semi; quantitative vs qualitative; internal vs external; volume / velocity / variety as the *challenge*, not a Hadoop course. Quality, missingness, redundancy, governance are inputs to whether the decision is even possible.

Measurement-scale *inference* (therefore ANOVA) → **BUS204**. Warehouse architecture as a *course* → **BUS250** Unit 3 / **BUS611**.

**Levels of analytics** (Bourgeois / OpenStax 8.2 school-common four):

| Level | Asks | Use when |
|---|---|---|
| Descriptive | What happened? | Baseline, KPI, “are we here” |
| Diagnostic | Why? | The Google case lives here |
| Predictive | What will happen? | Forecast, churn, demand |
| Prescriptive | What should we do? | The decision — this course’s point |

More advanced is not automatically better. The **decision** names the level. OpenStax 8.3 named methods at recognition depth: classification / trees, regression, clustering. **Hand off BUS204** for proofs; **CS250** for code.

**Correlation ≠ causation** is in-school (OpenStax 8.1). Do not let a strong r close the decision.

### Check D — Derive the insight; tell the story (when “what does it mean / show the board” is in play)

CLO 5–6. OpenStax 8.1 process: define the **problem** → prepare → analyze → interpret (**visualizations**) → **implement**. Data that is not acted on is not DDD.

**Insight** = a claim that **changes a decision** (live Google: *these* manager behaviors). A chart is not an insight.

**Visualization (CLO 6):** best practices **for different audiences**. Catalog: illuminating viz that tell a **data-driven story** leaders can use. Match graph to data type (Check C) and to the decision (Check A). Executives get a dashboard/KPI story; analysts get the table; ops gets the exception heatmap. Chart junk, truncated axes, and 3-D pies are the failure modes.

**Hand off BUS612 / PRDV200** if they want the comms *course*. Stay here for “this picture is how the leader will decide.”

### Check E — Spend it: CRM / database marketing and other strategies (when customers, campaigns, or “which strategies improve” are in play)

CLO 5, 7. Unit 7 is the live application: segment, predict response/churn, personalize, measure lift, then **decide** (retain, acquire, kill the campaign). Customer trends are CLO 5’s named object.

CLO 7: **business strategies that can be improved** through DDD — marketing is the named unit; finance / ops / HR are OpenStax 8.3 overlays (the Google case is HR). Do not run a full marketing-mix course (**BUS203 / BUS602**). Do not run the CRM database (**BUS611**).

Ads-that-follow-you (OpenStax 8.1) is the consumer-side of this unit — and the Unit 8 misuse if consent/privacy is skipped.

### Check F — Uses, misuses, strategy test (when “are we allowed / is this ethical / did strategy actually move” is in play)

CLO 8 + Unit 8 title.

**Use:** the insight changed what the firm *does*, inside the three continuums, with a leader who owns it. That *is* competitive advantage.

**Misuse (encode names, not dumps):** surveillance / sold PII; bias in the model; correlation as cause; p-hacking / dashboard theater; “the data says” as a way to dodge accountability. GDPR-class privacy / right to be forgotten is **course-era** in OpenStax — re-fetch for current law. Cambridge Analytica is Bourgeois’s named cautionary. Google People Analytics is the live *use*; it becomes a misuse if it is only a scorecard used to punish.

Then **stop**. If they need a full ethics course → **BUS200**. If they need a privacy/security course → **BUS206** / OpenStax ch. 6 as MIS. Stay here for “this insight is or is not allowed to drive strategy.”

## 2. Worked micro-patterns

**"What is data-driven decision-making / how is it not stats or BI?"**
Check A in one paragraph. Data > intuition. Goal = competitive advantage. Hook: BUS204 *infers*; BUS250 *stands up BI*; this course *decides*. Name Google People Analytics. Name the overlays: BUS610 is advanced BI; BUS612 is comms; CS250 is code.

**"We bought a data lake / nobody uses the dashboard."**
Check B. Which continuum ran ahead (almost always tech)? Leadership (CLO 3) has to put a decision on the dashboard. Do not prescribe a new tool.

**"Structured or unstructured / what level of analytics?"**
Check C. Name the type. Pick the **level the decision needs**. Do not climb to prescriptive because it sounds graduate.

**"Show this to the exec team / which chart?"**
Check D. Audience-fit story. One claim that changes a decision. Hand off BUS612 if they want the comms course.

**"How do we use this for CRM / churn / the next campaign?"**
Check E, then F. Segment → predict → decide → measure. Privacy/consent is the Unit 8 gate.

**"The model says fire these managers / sell this list / the correlation is 0.9."**
Checks C + F. Correlation ≠ causation. Google People Analytics used data to *change manager practice*, not to launder a purge. PII sales and biased scores are misuses.

**"Run the t-test / what’s the p-value."**
Wrong course. **BUS204**.

**"Stand up the warehouse / pick Tableau vs Power BI as intro."**
Wrong course. **BUS250** (intro) or **BUS610** (graduate BI). Recap viz-for-a-decision only if this prompt still needs it.

**"Write the pandas pipeline."**
Wrong course. **CS250**.

**"MMKT607 data-driven decisions / MEI607 DDD."**
Those codes are **not** this course (BI & Analytics; Creativity). Twins: **MBA607, MMGT607, MMKT609**.
