# Graduate data-driven communications: objective → analysis → viz → evaluate → story (clustered)

**Use when:** a task asks how a practitioner should **select and structure data for visual communication** — name the business objective before sourcing, run analysis only so there is something to say, apply graphic-design and storytelling principles, discriminate theoretical aspects of viz design, describe interactive visualizations and dashboards, evaluate the picture, and present findings, helpful facts, and data insights as a story — in the Saylor BUS612 **graduate** data-driven-communications school.

This is **one** skill. It is not "Unit 1 skill + Unit 2 skill…". BUS612's six live units are one argument: **data explosion gave us analysis tools and visualization; data-driven communication unlocks everyday business data as a competitive asset by selecting and structuring it for visual communication — objective first, analysis as input to the picture, principles and theory, tools including interactive dashboards, evaluate, then story so the finding conveys.**

## 1. Procedure — answer a graduate data-comms question in six checks

Run in order. Skip a check only if the user already constrained the frame.

### Check A — Identity, objective, source (always)

**The course question:** is the user asking for an **intro BI definition**, a **stats inference** answer, an **MIS survey**, a **Python implementation**, a **DBMS / data-management plan**, a **manager's D3M decision**, a **BI function across the lifecycle**, a **bizcomm memo/speech**, a **9 h mini viz**, or a **data-driven communication** that has to name the objective, source the data, and then select and structure it so findings actually convey?

Live test:

| Prompt smells like | Hand off |
|---|---|
| "What is BI / warehouse / Tableau as intro" | **BUS250** |
| "Stand up the BI team / mine text / warehouse *this* BI case / dashboard the decision-maker as an intelligence product" | **BUS610** |
| "Pick a DBMS / write the data-management plan / SQL create-edit-retrieve / share or not" | **BUS611** |
| "Sample, CLT, p-value, regression as inference" | **BUS204** |
| "Five components, CIA, does IT matter" | **BUS206** |
| "pandas / matplotlib / fit a sklearn model" | **CS250** |
| "Which decision, which bias, CRM file, uses vs misuses" | **BUS607** |
| "Memo / speech / crisis / audience-purpose-channel-tone" | **BUS210** |
| "9 h dashboard mini / craft a basic chart as PD" | **PRDV200** |
| "Name the objective, source for the picture, viz principle/theory, interactive dashboard as a technique, evaluate, story the finding" | **this skill** |

**Primary goal:** findings, helpful facts, and data insights **convey**. That is not "pass Tableau," not "ship a BI dashboard product" (**BUS610**), not "define BI" as intro (**BUS250**), and not "write the DBMS plan" (**BUS611**).

**Named live failure mode:** the firm already has a **data explosion** and analysis tools and still cannot **select and structure** a picture a stakeholder can use. Collection and computation without a communication objective is not this course's pass.

**Level check:** if the prompt is actually undergrad homework in BUS250's eight units, **hand off BUS250** and recap only. If it is BUS210 homework, **hand off BUS210**. If it is MBA612's / MMKT608's proctored 80% exam, **refuse exam reconstruction**; this skill is the *content* overlay, not the degree exam.

OpenStax §8.1 overlay (summarize, **do not dump iris/Python**): problem definition is step 1 of the analytics process; acquisition is not a fishing trip. The unit title puts **objective before source**.

### Check B — Analysis as input to the picture (when "which method / model / process" is in play)

CLO 1–3 on the **analysis** half. Unit 2.

The verb trio is still **identify / differentiate / apply** — the analysis has to be *sayable*, not merely computed. Live intro: analyzing data used to be hard; tools now uncover **valuable insights**. Those insights are the payload Unit 6 will story.

Encode:

1. **What business objective** Check A named (the analysis is in service of that, not a fishing expedition).
2. **Which process / method / model** is actually being applied (the CLO is differentiate *and* apply — two methods that answer different questions cannot both be "run the model").
3. **What would have to be true** for this result to be structur-able as a visual (Unit 3–6). An analysis that cannot be structured for visual communication fails *this* course even if it would pass a stats course.

OpenStax §8.1 overlay (summarize): statistical analysis uncovers patterns; **correlation is not causation**; interpretation is the next step and it usually *is* a visualization.

**Hand off BUS204** if the prompt is sample/CLT/p-value. **Hand off BUS610 Unit 3 / 5** if the prompt is mine-text / produce an intelligence product. **Hand off CS250** to code the model. **Hand off BUS611** if they need the store the analysis sits on. Stay here for "this method, this model, as the input to a picture a stakeholder can read."

### Check C — Viz principles, processes, and theory (when "which principle / which theory / how should this be designed" is in play)

CLO 4–7. Unit 3.

CLO 4–5 (graphic design + storytelling *styles*) begin here as *principles*; CLO 6–7 are the **theoretical aspects of visualization design** pair (identify / define, then **differentiate**). Two theories that recommend opposite encodings cannot both be "whatever looks nice."

This unit is **principles and processes**, not the tool list (that is Check D / Unit 4) and not the evaluation rubric (that is Check E / Unit 5).

Public school (confirm live labels; do **not** freeze Tufte/Gestalt/C.R.A.P. as Saylor doctrine until login):

- Signal vs noise / extra-ink.
- Chart-type fit to the comparison the objective needs.
- Clutter confuses.
- Accessibility (can the intended audience actually read it).
- Process: who is the audience, what comparison, what residual message.

BUS210 owns C.R.A.P. / Presentation Zen as *slide* craft — recap, do not paste that unit list. Wilke (CC BY-NC-ND author manuscript; **do not remix**): accurate, tell a story, look professional; a single static viz rarely carries a whole story arc — named jobs only.

**Hand off BUS250 Unit 5** if they want the intro named-form list (heat map / tree map / word cloud) as *intro*. Stay here for "which principle, which process, which theory of viz design."

### Check D — Tools, techniques, interactive viz, dashboards (when "which chart / dashboard / interactive" is in play)

CLO 8, CLO 9 overlay. Unit 4.

CLO 8: **describe interactive visualizations and dashboards.** Describe, not "pass Tableau Desktop." CLO 9 starts as "which technique presents the finding."

Gallaugher overlay (summarize, do not dump cases): **canned vs ad hoc** query; **dashboard** as a heads-up display of critical indicators; **OLAP / cubes** as a fast multidimensional *picture*. Privacy / export as a constraint on what you may show. BUS610 Unit 7 owns dashboards as *intelligence products*. Here the dashboard is a **technique** that still has to be evaluated (Check E) and storied (Check F).

OpenStax §8.2 overlay (summarize): visualization as graphical representation so leaders who cannot read a coefficient table can still see the insight; dashboards as multi-source one-page containers; Tableau / Power BI named as **industry examples**, **not** a live Saylor tool list. Do not add them as if the intro did.

Encode chart-type *fit* as a live job. Do **not** invent Saylor's named list until login. cmid `68990` guest-bounced this harvest — not a harvested type list.

**Hand off PRDV007 / Spreadsheet Mastery** for Excel chart mechanics. **Hand off CS250** for matplotlib. **Hand off BUS610** for the dashboard as a BI *product* across the lifecycle. Stay here for "this interactive viz / this dashboard, as a communication technique."

### Check E — Evaluate the visualization (when "is this a good chart / does this dashboard lie / would I ship this" is in play)

Distinctive unit (Unit 5). Neighbors fold "is this a good chart?" into reporting or tools. Here it is first-class. CLO 9 + the CLO 4–7 differentiate verbs: you cannot evaluate if you cannot tell two designs apart.

Public test (encode the *job*; confirm live rubric on login):

1. Does the picture match the **Unit 1 / Check A objective**?
2. Does it lie (truncated axis, 3-D pie, extra-ink — **named failure modes from the public school, not a confirmed Saylor list**)?
3. Can the intended audience read it (Check C accessibility)?
4. Is the interactive dashboard *explorable* or just noisy (Check D)?
5. Would Unit 6 be able to story this, or is it decoration?

Evaluation is not aesthetics-only. A pretty chart that does not serve the objective fails this check.

**Hand off BUS610** if they want KPI products / decision-maker-focused intelligence as the *BI function*. **Hand off BUS607 Unit 6** if they want viz best-practices *for different audiences* as the D3M story leaders use to *decide*. **Hand off PRDV200** if they want the 9 h "scan dashboards for misleading content" mini. Stay here for "is *this* visualization doing the communication job."

### Check F — Storytelling with data; present findings (when "tell the story / residual message / findings, facts, insights" is in play)

CLO 4–5 close here as **storytelling styles** (identify / define, then differentiate). CLO 9 closes as the **visual presentation of data analysis findings**. Catalog/info.php payload: **findings, helpful facts, and data insights**. Unit 6.

Live intro: competitive advantage from unlocking everyday data *by communicating it*. A story without a Check A objective is a slide deck. A story without Check E evaluation is decoration. Knaflic *Storytelling with Data* is the **ARR title-match** — name the job (context, audience, clutter, residual message), **do not dump the book**.

Public-school triad (data + visual + narrative) is a Coursera/vendor commonplace — **not confirmed as Saylor's list**. Encode the *job* even if the triad is unconfirmed: the finding has to travel.

**Hand off BUS607** if the prompt is "which decision, which bias, tell a story *leaders can use to decide*" as a *course*. **Hand off BUS210** if the prompt is a speech, a memo, a crisis statement. **Hand off PRDV200** if they want the 9 h mini. Stay here for "this data story, this visual presentation of the analysis."

## 2. Worked patterns (shape only — not exam items)

**"Leadership wants a dashboard of everything we collect."**
Check A (which objective is the dashboard for — "everything" is not an objective) → Check B only for the analyses that serve that objective → Check C (which principle / theory of encoding) → Check D (dashboard as a *technique*, canned vs ad hoc, interactive vs noisy) → Check E (does this dashboard actually communicate, or is it a data dump) → Check F (what residual message survives a glance). Do not turn it into a Tableau workbook dump or BUS610's intelligence-production project.

**"We ran a regression. Make it pretty."**
Check A (what business objective was the regression for) → Check B (is the model *sayable*, and is correlation being sold as causation) → Check C/D (which visual presents the finding) → Check E (does the picture lie) → Check F (findings / facts / insights). **Hand off BUS204** if they want inference as a course. **Hand off CS250** to plot it. Stay here for the communication job.

**"Is this 3-D pie OK because the CEO likes it?"**
Check E first (evaluate against the objective and the audience), then Check C (which principle/theory you are differentiating), then Check F only if a story can still be told after you refuse the lie. Aesthetics-only is a fail.

**"MBA612 / MMKT608 / MMGT612 / MEI612."**
**MBA612** and **MMKT608** exist as this title. MMGT608 is Applications of MIS. MEI610 is a seminar. Do not invent twins. Do not treat the free 70% certificate as those 80% proctored exams.

**"Just pick a chart type."**
Check A (what comparison the objective needs) → Check C (principle/theory) → Check D (technique). Chart-type *fit* is the job. Do not invent Saylor's named list until login. Do not dump Knaflic's chart chooser.
