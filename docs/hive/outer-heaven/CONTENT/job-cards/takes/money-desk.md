## 15. `f4mI3d-nTrI` — MCP goes stateless

**Transcript said:** The old MCP minted a session ID on initialize, which pinned the client to one server instance and broke behind load balancers unless you added sticky sessions or Redis. The new spec drops the handshake and the session header; each request is independent, so any instance can serve it and the process can scale to zero on Workers or Cloud Run. State, if you want it, is an explicit handle you pass as an argument, the way HTTP APIs always did. Follow-ups become a multi-round `input required` instead of a surprise push. Long work becomes a task you poll. SDKs major-bump; twelve-month deprecation window.

**Money Desk take:** Scale-to-zero and no session store is a hosting-cost win for Path C tools we already run. We do not SKU a protocol. Cheaper infra is not a vendor-approval. If Forge adopts the spec, we only care that pay/send paths stay gated and we are not paying Redis to hold a handshake we no longer need.
