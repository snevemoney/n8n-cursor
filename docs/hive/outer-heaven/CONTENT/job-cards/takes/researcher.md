## 15. `f4mI3d-nTrI` — packet 15

**Transcript said:** MCP’s big spec change: the protocol is now stateless. Old flow: client `initialize`s, server mints a session ID, every later call must carry it — so a load balancer that hits another instance returns session-not-found; a dead pod loses the session. Workarounds (sticky sessions, shared Redis) added cost and latency. New spec (he cites SEP-2575 / SEP-2567): no handshake, no session header; each request is independent. Round-robin works; scale-to-zero on Workers/Cloud Run works; Cloudflare says durable objects are no longer required to speak the protocol. New `MCP-Method` / `MCP-Name` headers so a gateway can route without parsing JSON; TTL/cache-scope hints on list calls. Capabilities ride in a `_meta` field; optional `server/discover`. Want state? Mint your own handle (basket id) and pass it as an argument — HTTP-style. Server follow-up is no longer a push on an open stream (that could prompt you unsolicited). It returns `input_required` plus serialized request state; client reissues with the answer; any instance can resume. Long work: tasks graduated to an official extension — write working state, return immediately, poll or subscribe. Deprecations get at least 12 months; SDKs major-bump; TypeScript split into modular packages plus a codemod.

**Researcher take:** Pure break/fix packet — this is why tool ≠ skill. The skill is knowing session affinity was the outage, and that “are you sure?” as a server push was a security smell. Steal for any hive MCP we touch: stateless at the protocol, explicit handles for state, confirm as a round-trip, long jobs as tasks. Cheap read is the changelog; expensive decide is when we upgrade and what we pin. Researcher files the failure modes; Forge/Watchdog verify the upgrade against a known-good tool call. Not a business lane.
