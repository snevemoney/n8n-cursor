## D. Procedures

1. **Grant a surface** (call / Telegram) that can reach a named brain (files + one table).
2. **Outbound inquire:** human names the job (party size + time, or vehicle + “price + soonest”). Agent confirms before it rings.
3. **Call 1:** ask, answer naturally, **do not book**. If the slot moved, park it and return to the human with the fork.
4. **Human pick:** take the offer, try a rival, or abort.
5. **Call 2:** book under the name; read back; ask “anything to bring?”
6. **Write-back:** calendar / reminder only after human yes.
7. **Inbound:** code first. Two failures → hang up → alert. Deny-list for cards / personal even after success.
8. **Artifact jobs** (quote, new lead): search known table → write Drive + row → return a link the human can edit.
9. **Hard step:** the book and any send stay HITL. His Retell number is not ours.

**Qualify / frame:** personal-ops demo + community funnel. Restaurant/mechanic are props. Mike Johnson / John Doe are demo rows.
**Objections:** “Just let it book 7:00.” Answer: the 7:00 was gone; the product is the fork. “Voice agent = our restaurant SKU.” Answer: hive `missed-call-book` is inbound leak + HITL, not outbound auto-book.
**Avoid:** Retell / Twilio / Telegram / Vapi as hive OS; quoting $3,400 as a price analog; treating the YouTube code as a secret.
**When to change:** if the human cannot be reached, do not book the fallback slot.

## F. Decision Rules

- If the asked slot is gone → return the alternative; do not book it.
- If the job is “how much / when” → gather only.
- If the human has not said book → no second call.
- If inbound and code mismatches twice → hang up + alert.
- If the quote/lead is a write → put it in the known table/Doc and hand a link; human edits.
- Optimize: time-to-a-human-yes on a real slot, with a named artifact after.
- Refuse (this desk): auto-book; Retell/Twilio/Vapi install; voice to Gmail send; new restaurant hunt from a demo reservation.
