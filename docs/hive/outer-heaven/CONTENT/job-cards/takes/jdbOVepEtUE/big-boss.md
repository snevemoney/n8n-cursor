## D. Procedures

**Non-coder first folder (his teaching sequence)**
1. Paywall/subscription on tape — we do **not** operate this. Analog: open the repo you already have.
2. Empty (or named) folder → open as the workspace → trust only if you mean it.
3. Ask the agent to init a short router doc + a config folder (his CLAUDE.md + `.claude`).
4. Put secrets in an ignored env file; never in git; name keys by job.
5. Connect **one** tool from the open-tab list (API docs → key → test request).
6. Checkable stop: green test **and** the working how/endpoint written into the router so `/clear` does not amnesia.
7. Stay on a cautious permission mode until deny-lists exist; never give send/delete if the job is draft/read.

**One-task loop**
1. Pick one weekly trigger (paper audit: what fires you most, lowest risk).
2. Map the steps or just do them once with the agent watching.
3. Judge with taste; list what changed and why.
4. Write the correction into the skill/router (not only into the chat).
5. Re-run. First N runs: brief only, no side effects (inbox: “nothing was touched”).
6. After confirm, allow the one safe mutation (mark-read ignore bucket).
7. Re-run skills when the model changes.

**Verification (prove-its-work)**
1. Ask: if a human handed this over, how would I approve it?
2. Assign that check to the agent (open the page, submit bad emails, screenshot vs reference, compare sheet to source).
3. For UI: screenshot loop on; for animation: loop off.
4. For send-shaped jobs: test to a hardcoded private destination; prove it landed; then — and only then — talk schedule.
5. Localhost ≠ shipped. Live URL is a later HITL.
6. Before unattended: edge-case list (API down, weird input) → safe-fail (notify / halt / no external).

**When to stop**
1. Name the north star *before* build (one number, agreed “this would be success”).
2. Build until the number, then maintenance — not one more feature.
3. Unrelated next task = new chat (or written handoff if the same thread bloated).
4. If the process is linear, stop climbing the pyramid (script, not routine/agent).
5. If there is no pain at this brain-level, do not climb.

**Qualify / frame:** This is a vendor course for knowledge workers, not a client SKU and not a hive OS install.
**Objections:** “I need Claude Code to be AI-native” — the machines are folder, loop, proof, stop; the harness is on-tape. “Just use connectors / bypass / 210 sub-agents” — portability, walls, and session limits are his own hedges.
**Avoid:** Installing Claude Code/Cowork/Codex; joining Skool; quoting tape $; deploying Modal/Vercel; auto-send; treating localhost as live; treating the 2h AIOS CTA as required.
**When to change:** File unnamed / process unmapped / no north star / tool can send → stop. Context rotting / agent off the rails → stop, handoff or rewrite the door-label.
