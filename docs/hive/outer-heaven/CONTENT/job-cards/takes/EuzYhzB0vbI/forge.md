## B. Atomic Knowledge

### A loop is trigger + action + checkable stop
- **Claim:** Loop engineering replaces you as the person who prompts. The loop is not “keep going until it feels good.”
- **Reasoning:** Without an objective and a check, a swarm just scales bugs.
- **Mechanism:** reason → act → observe → check done → stop or again. Hard cap on passes.
- **Evidence:** Cake-fork; thumbnail “until satisfied” fail; Abbey ≥9 / cap 8 and still not the photo.
- **Conditions:** Knowledge-work and build loops where a tool can observe the output.
- **Exceptions:** Subjective scores need a dedicated checker, not self-grade.
- **Action:** Write X metric = Y, how it checks, hard stop, before a run. Do not rebuild `coverage-loop`.
- **Confidence:** high on the shape; 27/37 min, 45 sources, V7 UNVERIFIED.
- **Source:** `EuzYhzB0vbI` @ UNKNOWN
- **Epistemic:** SOURCE

### Closer on first try ≠ 100% ≠ ship
- **Claim:** Loops raise attempt-one quality. They are not supposed to give perfect output.
- **Reasoning:** Abbey still looks nothing like the photo; the plane is not see-through.
- **Mechanism:** Verification + iteration vs one-shot “build me a 3D plane.”
- **Evidence:** Three Loop Library / `/goal` demos.
- **Conditions:** When the check tools exist (browser, screenshot, play, tone).
- **Exceptions:** If the check is the wrong modality (code-only for a photo), the loop cannot hit the photo.
- **Action:** `click-live-site` / play / tone must match the check. Do not deploy closer-looking HTML.

## C. Mental Models

## D. Procedures
1. Before a loop: write done = X metric = Y; check = visual / functional / play / tone; hard stop = N passes. 2. Give the agent the tool that can perform that check. 3. Prefer a separate checker when the score is subjective. 4. Plan first; log; watch cost. 5. Default solo. 6. If overnight: chunk 4–8h, then a human iterates. 7. Do not start because a tweet said “infer loops from vibe.”
