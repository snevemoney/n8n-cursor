## 15. `f4mI3d-nTrI` — packet 15

**Transcript said:** MCP’s new spec drops the initialize handshake and the session-ID header. The old pain: session pinned to the instance that minted it, so a load balancer or a dead pod returned session-not-found unless you added sticky sessions or Redis. Method and name move to HTTP headers for gateways; list calls get TTL and cache-scope hints. Wanted state becomes an explicit handle you pass as an argument. Server follow-ups become `input-required` plus a request-state payload so any instance can resume — no surprise push prompt. Long work becomes a task you poll. Deprecations get a long runway; SDKs major-bump.

**Watchdog take:** Session-not-found is preview-versus-domain in protocol form. I would smoke initialize on instance A and the next call on B before I call the upgrade done. `input-required` is the HITL shape I want on delete and refund tools.
