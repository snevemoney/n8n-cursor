## C. Mental Models
CLI is the real surface; the extension is training wheels. Parallel sessions are the OS; a dashboard is just the scoreboard. Long-running work is allowed if the stop is a metric. Research preview will be slow and buggy — expect it. Directory context is easy to lose when many agents share one pane. HITL (approve plan, reply from the view) is still in the loop.

## D. Procedures
1. Work in the CLI, not only the extension (his challenge for the week).
2. Left arrow → agent view. Right arrow → enter. `/bg` if a session is missing.
3. Spawn by typing a task in the view (he prefers this over flags).
4. Use flags/`cd` when the work is another directory; check cwd by entering the session (pane does not show it clearly).
5. Wrap flag prompts in quotes (brackets failed).
6. Yellow → space reply or approve. Ctrl+X twice to kill.
7. `/goal` only with an objective metric; expect hours.
8. If the machine crawls, remember research preview.

Questions: Needs input or done? Which directory? Is the goal a metric? Signals: yellow status, duration on the right. Qualify: more than one live session.
