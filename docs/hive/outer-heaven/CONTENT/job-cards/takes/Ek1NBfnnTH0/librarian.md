## D. Procedures
1. Write the root file as routes, not essays.
2. Segment any corpus that will keep growing on its own cadence.
3. Cron the Monday/Tuesday facts so they do not depend on memory.
4. Run a read-only audit; approve a fix list; do not let the auditor delete.
5. On a miss: replay the search, then patch the route.
6. Internal notes vs client-facing repo — OS knows the engagement, does not own the client git.
Avoid: Hyper Agent install; auto-fix; one mashed team wiki; Claude as hive.
