## C. Mental Models
Taste and loops outrank the logo. A frontier model is a teacher you distill. Effort is a dial, not a hero setting. Verify memory and files; answer first, then at most one question. Unit economics is a professional skill for small teams and personal budgets. Ownership = process + maybe hardware, never the API name.

## D. Procedures
1. When a run is loved and you cannot say why: have the model (or a cheaper one) analyze the session — thought, proof, path — and write a skill.
2. Five gates: scope (including what can go wrong) → evidence before reasoning → attack/adversarial → verify before done → report/calibrate.
3. Orchestrator plans; cheaper workers execute; report back.
4. Keep a routing table: models × cost × intelligence × taste (+ your columns).
5. Pick effort: 1 signal, 3–5 medium, 5–10 deep; if xhigh/max overthinks, step down.
6. Before trusting training memory or an implied file: check it exists.
7. Ambiguous ask: answer first, then one clarifying question.

Questions: Teacher or workhorse? What effort? What can go wrong? Signals: same quality at 3× cost. Qualify: task intelligence vs model intelligence.
