## D. Procedures

1. **Play, then extract:** run the strong model on a real job until you love one deliverable (or can open the session).
2. **Interrogate the win:** What did you think? How did you get here? How did you prove it worked?
3. **Write the skill:** five gates — scope (including what can go wrong) → evidence before reasoning → attack the plan → verify before done → report / calibrate.
4. **Route:** table of workers with cost, intelligence, taste. Officer keeps judgment; cheap models scout / execute.
5. **Set effort:** start below max; raise only if the verify gate fails.
6. **Checkable stop:** cheaper team’s output matches the loved artifact on a known-good, or you can name the miss.
7. **Do not own the vendor:** if the model disappears, the skill still runs on the stack you actually operate.

**Qualify / frame:** this is model-routing doctrine, not a client SKU. Fable / Opus / Sonnet / Haiku / Codex stay on tape.
**Objections:** “We need the best model” — answer with his Fable+Sonnet ≈ Fable+Fable lightbulb. “Always max effort” — he says max can be worse.
**Avoid:** installing Claude / Fable mode from Skool; quoting usage $ as FACT; spinning nameless sub-agent farms.
