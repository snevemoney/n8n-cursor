## C. Mental Models
Unhobbling / product overhang: today’s model can already do things the product has not exposed. Advice is perspective-bound (harness designer ≠ document maker). Good managers do not micromanage. Emotion in the done-line sometimes helps. Taste and judgment stay human.

## D. Procedures
1. On a new model: run old skills; if it feels degraded, fork and strip.
2. Keep a map of where things live; delete how-to that the model now knows.
3. A/B one real deliverable skilled vs empty.
4. Thin-skill the brand crumbs (header image, links, colors).
5. Goal = task + guardrails + exit + self-verify; optionally “10× QA, ship-ready.”
6. Devil’s-advocate agents allowed; understanding stays with you.
Avoid: sweep-delete the hive bible; AIS Plus / Skool; Claude Code as stack.
