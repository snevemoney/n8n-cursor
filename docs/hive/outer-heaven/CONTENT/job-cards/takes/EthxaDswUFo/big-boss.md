## D. Procedures

1. **Name the job class** before the bake-off: playable artifact, scroll taste, diversity gallery, or stateless Q&A.
2. **Same prompt both sides.** Do not tune mid-flight for one vendor.
3. **Play blind** when the artifact is comparable. Name the winner. Then open time / $ / tokens.
4. **Log bugs as first-class** (dead controls, menu overlay, leftover high score). They count.
5. **Split the score:** did it answer? vs was the answer better? vs was the artifact better?
6. **Ask the spend counterfactual** on the cheap side: if it spent the dear budget, would taste catch up? Do not assume yes.
7. **Assign role:** manager (judge, write, push back) vs worker (ship, verify, computer use).
8. **Match tier to task.** Classify-and-draft ≠ cinematic `/goal`.
9. **Do not rotate stack** from a day’s feel. Cursor + Grok stay.

**Qualify / frame:** this is a model-bake-off tape, not a client SKU and not an install order.
**Objections:** “Soul wins the benches / the API board” — answer with the bike and the cosmos pick, and with score-when-answering.
**Avoid:** quoting his $ / token / 24–3 as FACT; installing Claude Code, Codex, Soul, Fable, Open Router.
**When to change:** if the job is a cheap one-shot, do not spend the manager; if the job is taste, do not keep the cheap run because the receipt was small.
